==================================================
一、專案定位
==================================================

這是一個既有的 Python + Pygame 單機修仙 RPG 專案。

目標不是一次做成大型完整 RPG，而是先完成一個：
- 可以正常啟動
- 可以建立角色
- 可以修煉與成長
- 可以探索
- 可以使用背包與商店
- 可以打 Boss
- 可以存檔與讀檔
- 不容易 Crash
- 架構清楚
- 方便後續擴充

的 MVP 1.0。

核心玩法：

建立角色
→ 洞府
→ 修煉 / 打坐
→ 升級 / 境界突破
→ 探索秘境
→ 取得 EXP / 靈石 / 丹藥 / 裝備
→ 背包 / 煉丹 / 商店
→ 強化角色
→ 世界 Boss
→ Boss 獎勵
→ 存檔
→ 繼續循環

==================================================
四、Codex 修改專案前必須遵守
==================================================

1. 這是既有專案，不是空白新專案。

2. 修改前先掃描：
   - 目前資料夾
   - 所有 .py
   - 所有 JSON
   - imports
   - Scene 切換
   - 現有 UI
   - Save / Load
   - 現有可運作功能

3. 不得一開始就整套重寫。

4. 優先沿用現有可運作程式。

5. 不得因為「程式碼比較漂亮」而大規模改動正常功能。

6. 不得一次修改大量無關檔案。

7. 一次只處理一個明確功能或一組高度相關問題。

8. 修改後必須檢查：
   - Python 語法
   - ImportError
   - Circular Import
   - None 問題
   - KeyError
   - IndexError
   - FileNotFoundError
   - JSONDecodeError
   - Scene 切換
   - Button 重複觸發
   - Boss 重複發獎
   - 負數數值
   - 資料型態錯誤

9. 如果要重構，先說明：
   - 問題
   - 受影響檔案
   - 修改範圍
   - 為什麼要改

10. 若現有架構與本文不同：
    先分析實際程式。
    不要直接搬檔、改名、刪檔。

==================================================
十三、境界
==================================================

目前境界：

練氣期
築基期
金丹期
元嬰期
化神期
練虛期
合體期
渡劫期
大乘期

以上為目前正式九大境界。

每個大境界固定包含：

第一層
第二層
第三層
第四層
第五層
第六層
第七層
第八層
第九層

修為達到當前層上限後，突破至下一層。

第九層突破後，進入下一個大境界第一層。

九大境界的大境界突破必須使用對應丹藥：

練氣第九層 → 築基第一層：築基丹
築基第九層 → 金丹第一層：結金丹
金丹第九層 → 元嬰第一層：結嬰丹
元嬰第九層 → 化神第一層：化神丹
化神第九層 → 練虛第一層：煉虛丹
練虛第九層 → 合體第一層：合體丹
合體第九層 → 渡劫第一層：渡劫丹
渡劫第九層 → 大乘第一層：大乘丹

缺少對應丹藥時，修為停留在當前第九層上限，
不得扣除其他丹藥，也不得直接進入下一個大境界。

大乘期第九層為目前最高境界，修為不得超過該層上限。

飛升後境界不屬於目前 MVP，待專案開發到一定階段再擴充。

realm_index 對應九大境界，範圍固定為 0～8：

0 練氣
1 築基
2 金丹
3 元嬰
4 化神
5 練虛
6 合體
7 渡劫
8 大乘

舊版凡人境界僅保留作為存檔相容起點。

realm_index 必須檢查 0～8 上下限。

不得出現陣列超界。

十五、打坐與回血
==================================================

HP +10～30。

不得超過 max_hp / max_mp。

MP 已滿但 HP 未滿時仍可打坐回血。

HP 與 MP 都滿時不執行恢復。

任何情況：

0 <= mp <= max_mp

0 <= hp <= max_hp

- list

exp >= 0

一次操作

==================================================
四十八、低用量開發模式
==================================================

除非使用者明確要求詳細說明，所有 STEP 預設：

1. 一次只處理 1 個功能或問題。
2. 只讀取本 STEP 必要的檔案，不重複掃描整個專案。
3. 優先沿用前一 STEP 已取得的專案資訊。
4. 直接修改需要修改的程式碼。
5. 修改後執行必要測試。
6. 不主動大規模重構。
7. 不輸出完整程式碼，除非使用者要求。
8. 回覆保持精簡，只包含：
   【完成】
   【修改檔案】
   【測試結果】
   【下一步】
9. 使用者只輸入「下一步」時：
   依目前開發進度執行下一個最合理的 STEP。
10. 若下一步可能造成大型架構變更，先停止並詢問使用者。

==================================================
四十九、最後約束
==================================================

1. 不要硬套傳統 MVC。
2. 不要破壞 Scene Manager。
3. 不要把所有程式塞回 main.py。
4. 不要讓 UI 直接改 Player。
5. 不要讓 Object 依賴 Scene。
6. 不要使用 eval()。
7. 不要信任外部 JSON。
8. 不要讓一次 Click 執行多次交易。
9. 不要讓 Boss 獎勵重複領取。
10. 不要大規模改寫已正常運作功能。
11. 優先完成 MVP。
12. Python 修改使用自動重啟；JSON/Asset 優先 Hot Reload。
13. 架構清楚比形式上的 MVC 完整更重要。
14. 每次修改後必須測試。
